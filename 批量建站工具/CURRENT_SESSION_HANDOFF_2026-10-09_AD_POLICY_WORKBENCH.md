## 3. 后续修改必须保持的规则

### 3.1 页面、位置和单元分别独立

- `home`、`detail`、`all` 是三个页面类型。修改任一页面只作用于该页面类型。
- 广告位的放置位置与 banner 单元来源独立。位置1可使用 banner3，但仍在位置1选定的 DOM 间隙。
- 默认位置是导航下方、内容中段、页脚上方。用户已纠正第三个位置是“页脚上方”。列表中段按完整卡片行插入，不与广告3紧邻，整页居中。
- 同页重复使用同一 banner 单元时按现有规则关闭原位置，避免重复 DOM ID/广告定义。
- 新三页策略使用 `version: 2`；导出 manifest 外层仍可为 `sitefoundry-ad-policy/v1`，不要把两种版本概念混淆。

### 3.2 恢复基线不能被临时预设污染

恢复位置来源依次为：当前会话明确编辑并保存的该站位置 → `ad-policy.json.originalPlacements.positions` → 旧清单中保存的位置 → 原 HTML 的实际容器/可靠注释 → 默认位置。

实现细节：

- `original-banner1/2/3` 是按站解析原位置的 token，不表示所有站统一放置到同一物理位置。
- `capturePolicyOrigins` 对副本添加 `<!-- SITEFOUNDRY_AD_ORIGIN bannerN -->` 标记，保留各 HTML 文件的真实间隙。同类详情页之间也不能统一成第一篇的位置。
- 旧 `AD_POLICY_DISABLED` 源码块曾统一放在页脚，不能把该块所在位置当作关闭前位置。无可靠记录按用户允许的默认值回退。
- 脚本字符串中的 HTML 示例不能参与真实广告容器计数、删除或定位；移除广告要保护 script/style。
- `CONFIG.homeAds` 动态首页要同步处理，避免重绘后移动广告。
- 原位置清单即使关闭“写入禁用源码注释”也要保存在导出 manifest 中。
- `rememberPolicyPositions(site, policy, field)` 支持精确字段 `slots.(home|detail|all).(0|1|2).position`。工作台只记录用户实际编辑的位置；改单元或 OOP 开关不写入位置记录；选择对应原位置 token 则撤销该槽位的会话位置覆盖。
- 选择限流/简化预设本身不更新恢复记录。限流时编辑某站某页某一广告位，只更新那一个；全局位置编辑只更新未开启单站覆盖的站点。
- 预览和正式导出传入 `preserveOriginalPlacements: true`，临时输出策略与恢复基线分别保存。共享引擎该参数有兼容默认值，新调用方必须明确自己的用途。
- 最终实现没有使用 `adPolicyAppliedPreset` 全局标记追踪各站来源；不要重新引入容易污染单站恢复记录的全局判断。

“完全恢复广告”会清除所有单站广告策略覆盖，重新启用各站广告，但保留各站位置恢复记录与 TXT 替换。它与“恢复原站广告代码”是两个不同操作；后者只撤销指定站 TXT 替换。

重新导入策略包时，已有策略作为该站覆盖继续生效，不能导入后自动恢复成全局默认。用户主动选择完全恢复时才执行恢复。

### 3.3 原文件与预览约束

上传源包、用户数据源、桌面广告 TXT 和非目标二进制资源不能被修改。测试变体写入 `coverage`。`AdPolicyPreview` 使用 Blob URL 时应释放旧地址，消息需校验当前渲染 token 与 iframe 来源，自定义路径解析失败应明确报错。
