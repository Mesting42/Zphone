## 实现

1. 游戏 RAR/7Z 引擎改用已有本地 libarchive 模块、Worker 和 WASM；ZIP 不再使用 CDN 回退。
2. 33 个字体家族、239 个字体文件及原始许可证保存在 `public/fonts`，合计约 7.25 MiB。
   `manifest.json` 记录 CSS/字体/许可证来源和字体哈希，生成的运行时目录为 `js/offline-font-catalog.js`。
3. `js/offline-fonts.js` 负责共享预览链接和导出。预览从本机读取，导出仅打包使用的字体、样式和许可证，
   首页、详情和更深页面均采用相对路径。缺少字体时明确阻止不完整导出，不降级到远程 CDN。
4. `js/offline-status.js` 在工作台内显示非阻塞状态；浏览器报告离线且当前数据或预览含远程资源时出现，
   联网或切换为全部本地素材时隐藏。不会下载、改写或删除用户外链，也不主动请求第三方探测网址。
   使用浏览器网络信号，不把单个外站故障认定为设备断网；局域网连接但无法访问互联网时，浏览器信号可能仍为在线。
5. 游戏 RAR/7Z 原有 `json-archive` 数据标记遗漏了包内图片权限，已补齐；这不扩大该格式的可执行 HTML 导入范围。
6. 独立本机服务与广告模板解析器随生产构建打包为 `dist/sitefoundry-server.mjs`，只监听 loopback。
   字体资源允许不透明 sandbox 预览加载；模板 API 保持原有本机和 Origin 校验，没有放宽 iframe sandbox。
7. `scripts/check-offline-assets.mjs` 在生产构建前检查本地资源及字体哈希，不访问网络。

## 启动与数据

源目录已经安装依赖时：先 `npm run build`，再 `npm run offline:start`。
运行源码开发服务器也能离线使用，但交付目录推荐使用独立服务。

完整复制 `dist` 后，Windows 可执行 `start-sitefoundry.cmd`；也可在该目录运行：

```text
node sitefoundry-server.mjs
node sitefoundry-server.mjs --port 5175
```

目标设备需要已安装 Node.js；本次没有制作 Windows/Android 安装包或捆绑 Node 可执行文件。
本机运行不需要 `npm install`，不下载字体或解压组件。

独立服务将自定义广告模板保存在用户目录 `.sitefoundry/ad-templates`，首次从分发包初始化。
可用 `SITEFOUNDRY_DATA_DIR` 指定持久目录；目录应包含或允许创建 `ad-templates` 子目录。
更新分发包不会覆盖已有模板。源码 Vite 开发/预览仍沿用 `public/ad-templates`，两种启动方式的后续模板修改不自动同步。
浏览器中保存的游戏目录仍遵循原有 IndexedDB 与浏览器 Origin 规则。

## 验证与边界

证据：`coverage/offline-20261013/results.json`、`unit.log`、`build.log`、导出 ZIP 和截图。

- 生产构建成功；3 个针对性单元文件、16 项检查通过。
- 隔离的新浏览器上下文禁用缓存来源并阻断所有外部 HTTP 请求，保留 localhost；
  浏览器离线信号独立模拟，避免浏览器全局 offline 模式同时切断本机服务。
- 资讯实际上传既有回归副本 `摇滚乐史.rar`，通过配置、真实本地斜体字体预览和 ZIP 下载。
- 游戏实际上传原始内置 `game-source-1.zip`（84 个游戏），并上传由其中两条记录/封面生成的 7Z 专项夹具。
  另以真实 RAR 验证本地游戏解压引擎，提取 49 个文件；不把它说成游戏格式 RAR 的完整 UI 流程验收。
- 资讯与游戏导出包分别包含 54、90 个 HTML 页面；各重开首页和一张详情页，检查本地字体实际注册并加载。
  未把所有 144 个页面逐页做浏览器验收。
- 全部 33 个字体家族在浏览器实际加载，239 个字体文件的构建产物哈希一致。
- 联网隐藏、断网显示及 390px 提示宽度检查通过；模板解析、保存、读取及重启服务后读取通过。
- 记录中外部请求、本地 HTTP 错误及页面脚本异常均为 0。
- 差异化生成器只做共享字体接入的源码同步和语法检查，按用户要求未运行其上传、审计、预览或导出测试。
- 没有运行全量回归。历史发布前回归不代表本次离线源码的全量验收。

导入素材中的外部游戏、远程图片、第三方脚本以及真实广告展示和 GA 上报仍依赖互联网。
离线可完成本地建站与导出，不表示所有用户导入的远程服务已复制为可离线运行的服务。
React/Next 源码导出仍保留原工程；以后重建该工程所需的 npm 依赖或外部服务遵循原工程条件。
