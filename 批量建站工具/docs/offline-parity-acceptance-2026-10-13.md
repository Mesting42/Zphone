## 范围与方法

用户明确排除“差异化精品建站”的实际工作流验收。资讯、游戏、批量建站、广告移植、策略、恢复、快速更新和成品注入均纳入。未执行差异化上传、预览或导出流程。

联网与断网使用相同材料、配置与成品字节；每组从空浏览器存储开始。断网组保留本机 HTTP，拒绝外部 HTTP/HTTPS，并设置浏览器离线信号。它模拟设备无互联网但本地服务运行；没有关闭整机网卡。浏览器生成时间和随机源固定，避免时间戳、随机推荐造成无意义差异；ZIP 容器时间与压缩字节不作为一致性依据。

广告与 GA 的配置、容器、路径、开关及调用契约参与验收；真实广告服务保持隔离，未验证广告填充、收入或 GA 实际收数。受批准的外部游戏、封面等链接继续保留 URL；断网无法加载这些外部内容，作为已知限制记录。

既有 Next 源码的离线重建还在 Node 子进程安装了外部网络拦截，避免只断浏览器、构建过程仍能联网。本轮未下载新的构建依赖；使用原项目已经安装的依赖。

### 导出一致性

- **38 对成功下载的 ZIP：6,294 个解压后文件全部字节一致，未发现增删或内容差异。**包括广告代码导出包和批量归档；并非 38 个互不重复的网站。
- 另有 1 对被体检阻止的游戏生成包作为取证材料，233 个文件也一致。它们通过浏览器测试观察器保存，未绕过产品门禁触发下载，**不计为导出通过**。
- 联网重开 16 站、52 条页面路径；断网重开 15 站、47 条路径。差额是断网未成功重新构建的 React 输出。现有 React 静态成品在两侧均已重开。
- 两侧各验证 240 条资讯记录、全部非图片字段及 240 张图片原始字节保持一致。对应普通、广告移植和三个批量站；数据样本包含重复用于不同工作流的材料，不代表 240 条互不重复资讯。
- 被测浏览器未记录未处理脚本异常；资源检查中外部游戏封面失败和本地 Blob 封面失败如上单独披露，不宣称所有请求均成功。

### 单元测试与重跑

36 个单元测试文件共 570 个不同用例。首次 569 通过，1 个全领域卡片网格矩阵用例超过默认 5 秒；单工作线程、30 秒超时重跑该文件，43/43 通过，矩阵用例约 8.8 秒。因此 570 个不同用例均取得通过结果，不是一次命令 570/570 的记录。基础单元集包含共享及既有模块测试，不计为差异化工作流验收。

浏览器初次运行也保留了失败日志：离线远程游戏封面的预期错误被旧断言当作失败；提示检查曾在页面异步初始化完成前执行；联网测试曾错误等待离线提示。仅调整测试脚本的等待和已批准外部资源分类后重跑，保留所有本地图片断言。未以修改产品或关闭体检让失败用例通过。

## 已确认的问题与修复建议

### 1. 游戏本地封面预览

`game-builder/js/generator.js` 优先使用 `PreviewImageCache` 创建的父页 Blob URL；游戏 srcdoc 为隔离来源，无法读取这些地址。已有 data URL 被缓存分支遮蔽。目录重载后联网和断网各 26 张封面失败；离线改造前备份也实际复现相同结果。

建议：游戏预览优先使用已存在的本地图片 data URL；将图片映射与缓存回收职责分开，保留原有 sandbox 隔离。覆盖导入、保存后重载、切换源和三类页面，不通过扩大 iframe 权限解决。

### 2. 72 款本地游戏导出引用

游戏文件和封面确实在生成包内：`games/` 与 `images/`。但 `data.json` 的 `gameFile`、`coverFile` 等元数据保留了根目录裸文件名，产生 144 个错误引用；另外三个游戏内部的“游戏目录”链接指向不存在的 `games/index.html`，产生 3 个真实坏链接。体检正确阻止下载；改造前备份也有同样的 147 项问题。

建议：采用统一的本地资源路径转换，在导出的数据副本中同步游戏与封面字段；修正三份游戏 HTML 的目录链接。保留上传原始数据、许可证与来源记录，并验证三处链接真正返回网站目录。保持体检启用，不将所有 JSON 引用排除。

取证包中 72 个游戏页面在两种状态都能打开且未抛脚本异常；这仅证明页面载入，未验完每款游戏的所有规则和玩法，也未将该结果计作 UI 下载成功。

### 3. 导入的 React 源码字体依赖

本工具已把自身/生成模板使用的字体放到本地，但导入的 PixelWire React 源码使用原有 `next/font/google`。联网重新构建通过，断网失败，拦截日志明确指向 `fonts.googleapis.com`。错误日志也出现过 Next 原生 SWC DLL 初始化提示；字体请求失败是确定存在的离线阻塞，不能保证替换字体之后无需进一步排查构建环境。

建议：在保留 React 源码导出能力的前提下，将实际使用的 Google 字体及许可证打包，转换为 `next/font/local`，记录转换清单。首先覆盖本轮真实源码样本和明确支持的写法；不对任意导入源码声称可自动完整离线构建。原有外部游戏 URL 的保留规则维持不变。

上述修复需用户确认，本轮未实施。
