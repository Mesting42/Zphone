# 批量资讯站建站自动化工具 — AdSense 递审与 SEO 优化版开发提示词

> 这是一份可直接交给编程 AI 使用的完整开发提示词。请把本文件视为产品需求与验收标准，不要只给方案、伪代码或演示页面，必须完成可运行实现并验证。

## 0. 你的身份与最终目标

你是一名资深前端架构师、静态站点生成器工程师、技术 SEO 工程师和网站质量审核工程师。

请开发一个在浏览器中运行的中文可视化工具，用于批量生成内容为英文的资讯类静态网站。生成的网站将先用于 Google AdSense 递审，通过后再启用广告。因此，本项目的目标是：

1. 批量生成可直接部署、可抓取、可访问、链接完整的高质量静态网站。
2. 将 SEO、内容质量、站点可信度、隐私披露和 AdSense 广告安全设计成产品能力，而不是仅写在说明文档里。
3. 在导出前执行自动质量检查，阻止明显不完整、虚假、重复、不可抓取或存在死链的网站进入“递审版”导出。
4. 每个“递审版”或“过审后广告版”网站至少包含 35 篇有效资讯文章，且每篇最终可见英文正文严格大于 800 个单词（至少 801 词）。这 35 篇文章必须内容真实、质量合格、正文彼此独立，并各自使用一张未被站内其他文章复用的独立封面图。

重要边界：任何工具或提示词都不能保证 AdSense 审核一定通过。产品文案只能使用“提高递审准备度”“发现风险”，不得展示“保证过审”“通过率”等承诺或伪造统计。

## 1. 指令优先级与开发纪律

当需求发生冲突时，按以下优先级执行：

1. 数据真实性、用户安全、Google 政策与法律合规。
2. 无死链、完整功能、可抓取的静态 HTML。
3. 内容价值、站点可信度、SEO、可访问性和性能。
4. 本提示词中的业务流程与主题配置。
5. 视觉差异化和动画效果。

开发规则：

- 先检查现有项目和已有文件；保留用户已有且与本需求无冲突的实现。
- 不得用 `...`、TODO、空函数、假数据、占位页面或仅能截图展示的 UI 代替实现。
- 不得生成虚构的作者、团队、邮箱、地址、获奖记录、浏览量、评分、发布日期、测试过程或事实。
- 用户输入和 Markdown 必须经过安全转义或白名单清洗，防止 XSS、HTML/属性注入和危险 URL。
- 若选择 React，必须先按当前官方文档创建项目，并使用支持静态生成/静态导出的方案，例如 Next.js App Router 静态导出或 React Router v7 的预渲染能力。无论使用什么框架，最终网站的核心内容必须存在于生成后的静态 HTML 中。
- 若不需要 React，优先使用原生 HTML、CSS、JavaScript，生成器本身无需后端即可运行。
- 第三方库只用于生成器；导出的网站不得依赖 CDN、远程 JSON 或客户端 JavaScript 才能显示主要内容。

## 2. 产品形态与技术选型

### 2.1 生成器

- 中文单页 Web 应用，在最新 Chrome、Edge、Firefox 中运行。
- 全部数据默认只在本地浏览器处理，不上传服务器。
- 支持导入 JSON 或 ZIP，预览、验证并使用 JSZip 导出完整站点 ZIP。
- 可使用 JSZip、FileSaver.js 和经过安全配置的 Markdown 渲染库；依赖需要锁定版本并提供清晰许可说明。
- 所有耗时步骤显示进度、错误原因和可恢复操作。

### 2.2 生成的网站

- 生成真正的静态 HTML、CSS、JS 和图片资源，可部署到 Nginx、Apache、Cloudflare Pages、GitHub Pages 等静态服务器。
- 首页、分类页、文章页及政策页面的主要文本、卡片和链接全部预渲染进 HTML；禁用 JavaScript 后仍能阅读和导航。
- JavaScript 只用于汉堡菜单、非必要筛选等渐进增强功能。
- 全站内容为英文；代码注释可使用中文。
- 所有页面共用统一的 Header、Logo、导航和 Footer。

## 3. 核心操作流程

将原来的五步流程升级为七步：

1. 站点身份与主题
2. 上传数据
3. 字段匹配
4. 内容质量检查
5. 结构与样式配置
6. SEO、政策与广告配置
7. 预览、质量审计与导出

已完成的步骤可以返回修改，但后续检查结果必须随配置变化实时失效并重新计算。

## 4. Step 1：站点身份与主题

### 4.1 主题

至少提供以下主题，并允许以后扩展：

| 主题 ID | 中文名称 | 英文示例名称 | 默认方向 |
|---|---|---|---|
| `tech` | 科技资讯 | Technology News | 科技解释、软件、硬件、AI、安全 |
| `game` | 游戏资讯 | GamesInfo | 游戏资料、评测、攻略、行业资讯 |
| `food` | 美食资讯 | FoodHub | 食谱、烹饪技巧、饮食文化 |
| `anime` | 动漫资讯 | AnimeInfo | 动漫资料、评论、季度指南 |

示例名称只用于界面演示，不能直接进入“递审版”网站。用户必须确认或修改实际站点名称。

### 4.2 递审版必填的真实站点信息

- `site_name`：真实站点名称。
- `site_tagline`：准确描述站点价值，不使用夸张承诺。
- `site_description`：站点主题、目标读者和内容范围。
- `base_url`：正式 HTTPS 域名，例如 `https://example.com/`；用于 canonical、sitemap 和 Open Graph。
- `publisher_name`：真实个人、团队或组织名称。
- `contact_email`：真实可收信邮箱。
- `copyright_owner`：真实版权主体。
- `default_author_name`：仅在确实由该作者创作或审核时使用。
- `editorial_process`：内容如何研究、创作、事实核查、更新和纠错。
- `content_origin`：原创、人工编辑、AI 辅助或其他真实方式；不得隐瞒或伪造。
- `target_regions`：目标地区，用于隐私与同意管理提醒。

地址、电话、社交账号全部为可选项；未提供时不展示，禁止自动编造。

## 5. Step 2：上传数据与图片

### 5.1 JSON

支持：

- 数组：`[{...}, {...}]`
- 包裹对象：`{"articles": [...]}` 或 `{"data": [...]}`
- UTF-8 编码，显示总条数、字段名、字段类型、空值比例和前三条预览。
- 错误格式、重复 ID、异常长文本、非法日期或危险 HTML 必须给出具体提示。

### 5.2 ZIP 与图片

支持 JSON 与本地图片一起上传：

```text
upload.zip
├── data.json
└── images/
    ├── useful-descriptive-name.jpg
    └── another-image.webp
```

要求：

- 自动识别 `.json` 与 `.jpg/.jpeg/.png/.gif/.webp/.avif/.svg`。
- 重写为站内相对路径并防止 ZIP 路径穿越。
- 图片文件名转换为短、可读、小写、连字符分隔的描述性名称；处理重名。
- 用户必须确认拥有图片使用权或合法授权。工具不得替用户抓取、盗用或伪造图片授权。
- 在线图片可以用于草稿预览；“递审版”优先本地化。若因 CORS 或授权问题无法可靠本地化，必须提示并阻止把不可靠热链当作已通过检查。
- 读取图片尺寸，为输出的 `<img>` 写入 `width`、`height`，生成响应式尺寸；不得拉伸变形。
- 每篇有效文章必须拥有独立封面图。不同文章不得复用同一图片 URL、同一文件或内容相同但改过文件名的图片。
- 对本地图片计算稳定的内容哈希（建议 SHA-256），对可读取的图片额外计算感知哈希或等效视觉指纹；相同内容哈希一律判定为重复，视觉高度近似的图片进入人工复核。在线图片至少检查规范化后的最终 URL 是否重复；无法读取图片内容时不得宣称已完成内容级去重。
- 缺图时只允许在生成器的草稿预览中显示明确标注的临时占位图。缺图、破图或重复封面图的文章不得计入 35 篇有效文章，也不得进入“递审版”或“过审后广告版”。
- 输出“文章 → 图片路径或来源 → 授权确认 → 内容哈希/视觉指纹 → 去重状态”清单，以便逐篇复核。

## 6. Step 3：字段匹配

### 6.1 通用文章字段

| 字段 ID | 用途 | 递审版要求 |
|---|---|---|
| `title` | 页面标题与 H1 | 必填，每页准确且不重复 |
| `content` | 正文 | 必填，必须完整、有价值，不接受空壳内容 |
| `image` | 主图 | 必填，文件或 URL 必须有效 |
| `image_alt` | 图片替代文本 | 推荐；缺失时可根据真实标题生成自然描述，禁止关键词堆砌 |
| `excerpt` | 卡片摘要与 meta 描述候选 | 推荐，每篇需唯一 |
| `category` | 分类 | 必填，必须映射到存在的分类页 |
| `slug` | URL 路径 | 推荐；缺失时由标题生成并处理冲突 |
| `author` | 作者或审核者 | 递审版必填，可使用经过确认的真实默认作者 |
| `published_at` | 首次发布日期 | 递审版必填，必须为真实日期 |
| `updated_at` | 实质更新日期 | 可选；不得只为“显得新”而改日期 |
| `sources` | 事实来源或原始证据列表 | 包含事实性陈述的文章必填；优先使用官方、第一方或权威来源 |
| `source_url` | 原始资料来源 | 可选；存在时必须有效且与页面披露一致，不能代替原创内容 |
| `fact_checked_by` | 真实事实核验者 | 递审版必填，不得自动生成或冒用身份 |
| `fact_checked_at` | 最近事实核验日期 | 递审版必填，必须对应真实核验行为 |
| `cover_image_source` | 封面图来源或权属说明 | 递审版必填，用于记录原创、授权或合法许可 |

### 6.2 主题扩展字段

- 科技：`developer/vendor`、`version`、`platforms`、`requirements`、`tested_by`。
- 游戏：`developer`、`publisher`、`genres`、`price`、`platforms`、`release_date`、`store_url`。
- 美食：`ingredients`、`instructions`、`prep_time`、`cook_time`、`servings`、`cuisine`、`allergens`、`calories`、`recipe_url`。
- 动漫：`studio`、`genres`、`rating`、`episodes`、`season`、`air_date`、`official_url`。

只渲染已映射且有真实值的可选字段。字段未映射时隐藏对应元素，不得显示 `N/A`、空卡片或虚构默认值。

## 7. Step 4：内容质量检查

这是递审准备度的核心步骤，不得省略。

### 7.1 自动检查

- “递审版”和“过审后广告版”必须至少包含 35 篇通过全部硬性检查的有效资讯文章；有效文章总数少于 35 篇时标记为 `BLOCKER`。草稿、隐藏页、政策页、分类页、重复文章、无效文章和未达到正文单词要求的文章均不得计入数量。
- 每篇文章最终渲染后的正文可见英文单词数必须严格大于 800，即至少 801 个英文单词；800 个或以下一律标记为 `BLOCKER`，禁止导出“递审版”和“过审后广告版”。
- 单词数只统计文章主体 `article` 正文：先移除 HTML/Markdown 标记、脚本、样式、标题、摘要、作者信息、日期、导航、页脚、侧栏、广告、相关推荐和政策模板，再对可见正文统计英文单词。连字符词和含撇号的自然英文词按一个词统计；纯数字、URL、文件名和标点不计入。浏览器生成器与可选 Python 生成器必须使用一致、可重复的统计规则。
- 在数据预览、文章检查结果和最终审计报告中显示每篇文章的准确正文单词数，并提供“小于要求的文章”筛选和定位功能。
- 空正文、无法完整回答主题的页面、重复标题或完全重复正文必须拦截。对清洗后的正文计算内容哈希，任何两篇内容相同的文章均为 `BLOCKER`；不得通过修改标题、slug、作者、空白或标点规避去重。
- 上传数据不足 35 条，或经过清洗、去重和校验后有效文章不足 35 篇时，界面必须显示“当前有效文章数 / 35”和仍缺少的篇数，并定位被排除文章及原因。
- 对正文主体执行站内文本指纹和相似度检查，并排除 Header、Footer、作者框、免责声明等共享模板。高度相似、只替换少量词句或套用同一模板扩写的文章标记为 `BLOCKER`，展示相似文章对、重复片段和相似度证据，要求实质性重写。
- 每篇文章检查封面图唯一性。重复图片 URL、重复内容哈希、同一图片的改名副本均为 `BLOCKER`；视觉高度近似但无法自动确定的图片标记为 `NEEDS MANUAL VERIFICATION`，未完成复核前不能计入有效文章数。
- 检查占位文本与伪信息：`Lorem ipsum`、`TBD`、`Coming soon`、`example.com`、虚构联系方式、全零发布商 ID 等。
- 检查标题与正文主题是否明显不一致、分类为空、文章只有图片/链接没有主体内容。
- 检查批量同义改写、简单翻译、拼接他站内容、关键词堆砌和大规模低价值页面风险。
- 检查事实字段是否自相矛盾，例如发布日期、价格、平台、评分和正文描述冲突。
- 检查每篇事实性文章是否提供可访问且与正文相关的来源或原始证据、真实事实核验者和核验日期。来源打不开、来源与主张不相关、仅引用低质量聚合页或核验状态缺失时，不得标记为“真实性已确认”。
- 工具不得自动补写未经来源支持的事实、数字、引语、人物经历、价格、发布日期、评分、研究结论或第一手体验。数据缺失时应要求补充或删除该主张，不得猜测。
- 提示拼写、断句、异常编码、残留 Markdown 和不可见字符问题。

### 7.2 内容原则

- “正文大于 800 个英文单词”是本项目的业务硬标准，不得表述为 Google 官方最低字数，也不得暗示达到字数即可通过 AdSense。即使超过 800 个单词，页面仍必须完整解决用户问题并具有真实价值。
- 禁止为了达到 801 个单词而使用重复段落、空泛套话、无关内容、关键词堆砌、隐藏文字或批量扩写废话；发现明显凑字数行为时仍标记为高风险或阻塞项。
- 内容必须为用户而写，包含原创信息、分析、经验、验证、清晰步骤或其他实质增量，不能只为了覆盖关键词。
- 每篇文章必须具有独立选题角度、独立正文结构和独立信息价值；不得把一篇母稿仅替换产品名、关键词、地区、人物或少量句子后批量发布。
- 真实性以可核验来源、原始资料、真实作者或编辑责任和人工事实核验为依据。自动规则只能发现风险，不能独立证明互联网上的所有陈述为真；产品必须如实显示“自动检查通过”“人工已确认”或“仍需验证”，不得把未验证内容标成真实。
- 页面应清楚说明谁创作或审核、如何产生内容以及为何对读者有用；需要时提供作者页或编辑说明。
- 不得生成假评测、假体验、假排行榜、假下载按钮或无法兑现的功能。
- 涉及健康、安全、财务、法律等高风险内容时，必须展示准确来源、审校信息和适当免责声明；缺少可靠证据时阻止递审版导出该内容。
- AI 辅助不等于违规，但大规模生成、缺少原创价值或以操纵排名为目的的内容属于高风险。需要披露时生成真实、简洁的制作方式说明。

自动检查只能提示风险，不能把分数包装成 Google 官方评分或审核结论。

## 8. Step 5：结构与样式配置

### 8.1 全站结构硬要求

- Header 中必须有网站 Logo；Logo 使用真实 `<a>` 链接到首页。
- 所有页面使用相同 Header、导航和 Footer。
- Footer 在首页、分类页、详情页、404 页以及所有通用页面中都必须显示以下四个可点击链接，且不可关闭：
  - About Us → `/about/`
  - Contact Us → `/contact/`
  - Privacy Policy → `/privacy/`
  - Terms of Service → `/terms/`
- 首页打开后能在首屏或轻微滚动范围内看到真实内容卡片；禁止用超大 Hero 长期遮住主体内容。Hero 默认关闭，开启后也必须克制。
- 二级页面顶部提供可正常返回首页的面包屑或按钮。
- 分类导航必须进入真实存在且包含内容的分类页；空分类不得生成或显示。

### 8.2 卡片交互

- 整张卡片只能由一个覆盖完整卡片的 `<a href="真实文章路径">` 实现可点击，键盘可聚焦。
- 不得只让标题或“Read More”局部可点击。
- 卡片中的图片、标题和摘要必须与目标页一致。
- 若卡片内确实需要第二个交互控件，避免嵌套交互元素；重新设计 DOM 和可点击区域。

### 8.3 首页与详情页

- 首页包含明确 H1、站点简介、精选/最新内容和分类入口。
- 文章详情页包含 H1、作者、真实日期、分类、正文、主图、相关内容和返回路径。
- 相关推荐优先按相同分类或标签确定性生成；排除当前文章，避免每次刷新随机变化。
- 外部操作按钮仅在对应 URL 存在、协议安全、格式有效并经过确认时生成；否则完全隐藏。
- 科技主题不得再生成 `Read More` + `href="#"`。若正文已在当前页，不需要该按钮。

### 8.4 样式能力

保留并完善原有 12 套视觉风格：Starry、Cyberpunk、Minimal、Dark、Forest、Ocean、Retro、Gradient、Aurora、Lava、Sunset、Mint。

可配置导航布局、卡片边框/圆角/阴影、字体、网格密度、按钮、详情页图片布局和轻量动画。所有预设必须满足：

- 正文与背景具有可读对比度。
- 焦点样式清晰，不只依赖颜色表达状态。
- 支持 `prefers-reduced-motion`。
- 320px 至宽屏均无横向溢出。
- 装饰动画不阻塞内容、不造成明显布局偏移、不模仿广告或系统提示。

### 8.5 必须保留的结构配置能力

在不违反本提示词硬约束的前提下，保留原工具的灵活配置：

| 区域 | 配置项 |
|---|---|
| 全局 | 导航布局（常规/居中/左对齐）、Footer 版式（简约/详细）、返回首页样式（面包屑/按钮/文字链接） |
| 首页 | Hero 开关、3～8 个分类、分类名与图标、每类卡片数、响应式或固定列数、卡片字段、内容排序 |
| 详情页 | 元信息布局（grid/list/tags）、纯文本或安全 Markdown、外部操作按钮、2～8 条相关推荐、推荐卡片字段 |
| 视觉 | 主题色、字体、导航样式、卡片 hover、边框、圆角、阴影、间距、按钮、图片布局、轻量入场动画 |

补充规则：

- Footer 的四个强制链接不属于可关闭选项；用户只能选择版式和是否展示额外说明。
- 内容排序支持数据顺序、发布日期、标题、手动顺序和“生成时固定种子的洗牌”。禁止每次页面加载都随机变化，以保证静态 HTML、相关推荐、内部链接和测试结果稳定。
- 首页分类卡片数量不得超过有效文章数量，同一分类中不得重复同一文章；没有内容的分类自动隐藏并从导航、sitemap 中移除。
- 所有通过检查的有效文章都必须生成独立静态详情页，并至少从首页、分类页、分页或其他可抓取的站内路径进入，禁止产生孤立文章页。文章数量超过首页展示容量时，必须生成可抓取的分页或归档导航。
- Markdown 转换后必须清洗；不能把未经处理的原始 HTML 直接插入页面。

### 8.6 生成器界面

桌面端使用“左侧步骤导航 + 中间配置表单 + 右侧实时预览”的三栏布局；窄屏改为可用的纵向布局。要求：

- 步骤顶部显示进度与当前状态，已完成步骤可返回。
- 上一步/下一步不会丢失数据；刷新前提示未保存配置。
- 支持导入/导出生成器配置，配置带版本号并进行迁移或兼容提示。
- 配置变更后预览在合理时间内更新；大量数据使用节流、分批处理或 Web Worker，避免冻结界面。
- 第 7 步先显示配置摘要与审计结果，再分别提供“导出草稿”“导出递审版”“导出过审后广告版”。
- 草稿导出允许保留明确标注的未完成项；递审版和广告版必须遵守相应硬门禁。

## 9. Step 6：SEO、政策与广告配置

### 9.1 URL 与静态目录

默认使用短、描述性、小写、连字符分隔的 URL：

```text
/
/category/software-updates/
/articles/how-to-update-windows-11/
/about/
/contact/
/privacy/
/terms/
```

物理文件使用目录式静态输出，例如 `articles/how-to-update-windows-11/index.html`。Slug 冲突时稳定追加短 ID，禁止使用查询参数、下划线、无意义自增文件名作为默认公开 URL。

### 9.2 每页技术 SEO

每个可索引页面必须具备：

- 唯一、准确、自然的 `<title>`。
- 唯一的 `<meta name="description">`，准确概括可见正文。
- 一个且仅一个有意义的 `<h1>`；后续标题按 `h2 → h3` 逻辑嵌套，不跳级。
- 与 `base_url` 一致的绝对 canonical URL。
- 正确的 `lang="en"`、UTF-8、viewport。
- Open Graph 与 Twitter Card 元数据；值与可见内容一致。
- 合适且真实的 JSON-LD：站点可用 `WebSite`/`Organization`，文章用 `Article`，食谱仅在字段完整且页面可见内容匹配时使用 `Recipe`。禁止伪造评分、评论、作者或日期。
- 描述性锚文本，不使用大量含糊的“click here”。
- 不再依赖 `meta keywords`；可以兼容生成，但不得把它当作核心 SEO 能力或关键词堆砌入口。

### 9.3 图片 SEO

- 文件名短且描述性，使用小写字母和连字符，例如 `windows-11-update-settings.webp`。
- 每个内容图片都有与画面和上下文一致的自然 `alt`；装饰图使用空 `alt=""`。
- 禁止将关键词列表塞入 alt。
- 图片紧邻相关文本，写入宽高，使用响应式图片；首屏主图优先加载，非首屏图片懒加载。
- 图片错误时显示存在于站内的后备图，并保持布局稳定。

### 9.4 Sitemap、robots 与抓取

- 必须在根目录生成 UTF-8 的 `sitemap.xml`，只包含希望索引的 canonical 绝对 HTTPS URL。
- `lastmod` 仅在真实发生实质更新时写入；不生成无依据的日期。
- 必须生成根目录 `robots.txt`，允许抓取公共内容，并写入绝对 Sitemap 地址。
- 生成 `404/index.html` 或宿主兼容的 `404.html`，其中保留导航、搜索/推荐入口和 Footer 四个政策链接。
- 不得意外输出 `noindex`、阻止 CSS/JS/图片，或让 canonical、内部链接与 sitemap 使用不同 URL 版本。

### 9.5 About、Contact、Privacy、Terms

这四页是递审版强制页面，且必须使用用户提供的真实信息：

**About Us**

- 说明站点是谁运营、服务什么读者、覆盖什么主题、内容标准、编辑/更新/纠错流程。
- 只展示真实团队与经验；没有团队资料时不生成“Meet the Team”等虚构内容。

**Contact Us**

- 至少提供真实可用的 `mailto:` 邮箱链接。
- 仅当配置了真实可工作的表单端点时才生成表单，并实现成功、失败、校验和隐私提示。
- 纯静态站没有表单后端时，不得生成点击后无反应或假装发送成功的表单。

**Privacy Policy**

- 根据实际启用的分析、广告、Cookie、本地存储、表单和第三方嵌入生成，不得声称使用了实际未使用的服务，也不得遗漏已使用的服务。
- 启用或计划启用 Google 广告时，披露 Google 与其他第三方供应商可能使用 Cookie、个性化广告及用户退出个性化广告的方式，并提供真实链接。
- 包含生效/更新日期、数据用途、保留、共享、用户选择、儿童隐私、地区权利和联系方式；内容保持可编辑。
- 页面必须提示经营者根据所在地与目标地区获得适当法律意见，工具不得宣称模板构成法律意见。

**Terms of Service**

- 包含服务范围、允许/禁止行为、知识产权、外部链接、免责声明、责任限制、条款变更和联系方式。
- 主题特有提示必须真实，例如食谱过敏原/营养信息、软件操作风险、价格与发行信息可能变化。

### 9.6 AdSense 两种导出模式

**模式 A：递审版（默认）**

- 不导出假广告、灰色广告占位块、诱导点击文案或展示广告位。
- 可选填写真实 AdSense 站点验证代码或账号标识，并按用户提供的原始值放入正确位置；禁止生成假的 `pub-000...`。
- 若用户没有真实 publisher ID，不生成 `ads.txt`，并在检查报告中标为“尚不可验证”，而不是伪造文件。

**模式 B：过审后广告版**

- 只有用户显式开启并提供真实 publisher ID、广告客户端/广告位配置时才插入广告代码。
- 支持 Auto ads 或手动广告位，但不得重复加载 AdSense 脚本。
- 手动广告位使用响应式容器并预留尺寸，避免 CLS；广告不得遮挡内容或导航。
- 广告与正文、菜单、下载、分页、表单、游戏/工具操作区保持清晰间隔，不得模仿卡片、按钮或系统消息。
- 若添加文字标签，只能使用合规且不误导的标签，例如 `Advertisements` 或 `Sponsored links`。
- 页面主体内容必须明显多于广告，首屏仍能识别网站目的和主要内容。
- 不得提示站长或用户点击广告，不得支持无效流量、购买垃圾流量或自动点击。
- 若向 EEA、英国或瑞士用户提供个性化广告，必须要求使用当前 Google 认证且符合要求的 CMP；无法确认时阻止宣称“合规”，并列为待人工验证。
- 只有存在真实 publisher ID 时才生成根目录 `ads.txt`，内容使用用户实际从 AdSense 获取的记录，并检查根路径可访问性要求。

## 10. Step 7：预览、质量审计与导出

### 10.1 实时预览

- 支持桌面、平板和手机尺寸。
- 支持首页、分类页、详情页、About、Contact、Privacy、Terms、404 预览。
- 使用真实导入数据，预览 DOM 尽量与最终静态 HTML 一致。
- 预览中的假广告框只能存在于生成器 UI 内，并明确标注“仅预览，不会导出”；递审版导出不得包含。

### 10.2 链接完整性硬门禁

导出前构建全站链接图并逐项检查：

- 禁止空 `href`、只有 `#`、`javascript:void(0)`、错误相对路径、缺失文件和指向未生成页面的链接。
- 所有内部链接必须解析到 ZIP 内真实文件、真实目录首页或同页真实存在的锚点 ID。
- Logo、导航、Footer 四链接、卡片、面包屑、相关文章、图片、CSS、JS、favicon、canonical 与 sitemap 全部纳入检查。
- `target="_blank"` 的外链自动补 `rel="noopener noreferrer"`。
- 仅允许 `https:`、受控的 `http:` 升级提示、`mailto:`、`tel:` 和站内相对 URL；拒绝危险协议。
- 由于纯浏览器环境可能受跨域限制，不能自动获得所有外链的 HTTP 状态。对外链执行格式校验、去重，并提供“逐个打开验证/用户确认”流程；未经确认的外链不得作为“已验证”通过。无法验证时隐藏非必要按钮，或在递审报告中明确列为人工阻塞项，绝不谎报无死链。

只有内部链接错误数为 0、所有强制页面存在且 Footer 四链接可达时，才能导出“递审版”。

### 10.3 自动审计面板

按以下级别展示问题：

- `BLOCKER`：禁止递审版导出。
- `HIGH`：默认禁止，用户修复后重新检查。
- `WARNING`：允许草稿导出，不应标记为递审就绪。
- `PASS`：给出实际检查证据。
- `NEEDS MANUAL VERIFICATION`：工具受限，必须人工确认。

至少检查：

1. 必填真实身份信息和正式 HTTPS `base_url`。
2. 四个政策/信任页面及全站 Footer 链接。
3. 内部死链、资源缺失、外链确认状态。
4. 每页 title、description、H1、heading、canonical、lang。
5. sitemap、robots、404 和 URL 一致性。
6. 图片 alt、尺寸、文件名、破图、授权确认，以及每篇文章封面图 URL、内容哈希和视觉指纹的唯一性。
7. 有效资讯文章是否少于 35 篇，以及空页、空分类、占位文本、正文英文单词数不大于 800、重复/高相似内容和明显凑字数内容。
8. 作者、日期、编辑说明、来源证据、事实核验者、核验日期与尚未验证的事实性主张。
9. 移动端布局、键盘导航、焦点、对比度和减少动画。
10. 未清洗 HTML、危险 URL、重复 ID 和 XSS 风险。
11. Privacy 文案与实际脚本/存储/表单/广告配置是否一致。
12. 递审版是否误含广告占位或假 ID；广告版是否存在误点击和 CMP 风险。

审计结果必须可点击定位到具体页面、字段或配置项，并可导出 `site-audit-report.html` 或 `site-audit-report.json`。报告不得写“Google 一定通过”，只能写：

- `READY FOR MANUAL REVIEW`：自动检查范围内未发现阻塞项。
- `NEEDS WORK`：仍有需修复项。
- `NOT ASSESSABLE`：缺少关键真实信息或无法验证。

### 10.4 导出包

默认目录结构：

```text
website-export/
├── index.html
├── category/
│   └── {category-slug}/index.html
├── articles/
│   └── {article-slug}/index.html
├── about/index.html
├── contact/index.html
├── privacy/index.html
├── terms/index.html
├── 404.html
├── assets/
│   ├── css/style.css
│   ├── js/site.js
│   └── images/...
├── favicon.svg
├── robots.txt
├── sitemap.xml
├── ads.txt                 # 仅在有真实 publisher ID 时生成
├── site-audit-report.html
└── site-config.json        # 不得包含秘密或不必要个人数据
```

首页和每篇文章的主体内容必须直接写入对应 HTML，不得在上线后依赖 `fetch('data.json')` 才出现。

默认由浏览器端 JavaScript 直接生成全部静态文件并打包，这是必须完成的方案。可以额外提供面向超大数据集的 Python 命令行生成器，但它必须：

- 与浏览器生成器共用或严格遵循同一套配置、模板、URL、清洗和审计规则。
- 生成完全一致的目录语义与质量报告。
- 不得成为生成详情页、sitemap 或内部链接检查的唯一可用路径。
- 提供依赖说明、错误处理和可重复执行命令，不得只输出含 `...` 的脚本骨架。

## 11. 安全、可访问性与性能

- 使用语义化 `header/nav/main/article/section/footer`。
- 所有交互均可键盘操作，焦点顺序合理；汉堡按钮维护 `aria-expanded` 和 `aria-controls`。
- 表单有真实 label、错误提示与状态消息。
- 图片使用 alt；装饰 SVG 正确隐藏；Logo 文本可访问。
- 对比度、触控目标、行宽、字号符合常见无障碍实践。
- 使用原生懒加载、压缩图片、精简 CSS/JS、缓存友好文件；避免不必要第三方脚本。
- 为图片和广告预留空间，减少布局偏移。
- 外链、Markdown、结构化数据和用户输入全部验证/转义；禁止 `eval` 和内联拼接不可信 HTML。
- 生成器预览使用隔离 iframe 或等效安全边界。

## 12. 主题默认内容与差异化规则

允许为不同主题提供分类、图标、配色和 Hero 文案建议，但这些只能作为可编辑起点。不得通过简单更换颜色、站名或同义词批量制造高度相似网站。

每个站点必须有明确且聚焦的主旨、真实运营身份、独立的内容集合和站内结构。若多个导入站点的正文或页面高度相似，应给出规模化低价值内容风险提示。

主题默认分类示例：

- Tech：Hardware、Software、AI & Machine Learning、Cybersecurity、Industry。
- Game：Action、Puzzle、Adventure、Arcade、Strategy。
- Food：Quick Recipes、Traditional Cuisine、Desserts、Healthy Eating、World Cuisine。
- Anime：Action、Romance、Fantasy、Sci-Fi、Slice of Life。

只有实际有内容的分类才能出现在导航、首页和 sitemap 中。

## 13. 验收标准

交付前必须实际生成一套测试站点并验证，至少覆盖：

- JSON 数组与对象包裹两种格式。
- 本地图片 ZIP、缺图、重复 slug、特殊字符、Markdown 和恶意输入。
- 四种主题至少各生成一篇详情页。
- 使用 34 篇与 35 篇两组边界测试数据验证文章数量门禁：34 篇有效文章必须被阻止，35 篇有效文章才能通过数量检查；所有计数文章都必须拥有独立静态 URL 并可由站内链接访问。
- 每篇测试文章最终可见英文正文至少 801 个单词；审计报告中的计数与实际渲染正文一致。使用一篇恰好 800 词的测试数据验证其会被阻止，再使用一篇 801 词数据验证字数门禁通过。
- 使用正文完全相同但标题/slug 不同、只替换少量词句、高度模板化三类数据测试内容去重；它们都不得被计为独立合格文章。
- 使用同一封面路径、同一图片改名副本、内容相同但元数据不同、视觉近似图片四类数据测试图片去重。前 3 类必须阻止，视觉近似图片必须进入人工复核；最终 35 篇有效文章必须对应 35 张经确认的独立封面图。
- 使用缺少来源、来源与正文不相关、来源失效和未填写真实核验者的数据测试真实性门禁；系统必须显示准确状态，不能自动伪造来源或宣称事实已验证。
- 首页、分类页、文章页及四个强制页面在禁用 JavaScript 后仍可阅读。
- 桌面、平板、手机布局。
- Footer 四链接在所有页面存在并可达。
- 内部链接检查为 0 错误；不存在 `href="#"`、空链接和 `javascript:void(0)`。
- 每页唯一 title/description/H1/canonical。
- sitemap 中 URL 与 canonical 一致，robots 指向正确 sitemap。
- Contact 在无后端时不生成假表单。
- 递审版无假广告、假 publisher ID 和误导按钮。
- 广告版只有在真实配置开启时插入代码，且不会重复加载脚本。
- 浏览器控制台无未处理错误，导出 ZIP 可解压并部署。

最终交付内容：

1. 完整可运行源代码。
2. 清晰的启动、使用、构建和部署说明。
3. 一套不含虚构运营信息的测试数据，明确标注仅用于开发测试、不可用于真实递审。
4. 自动化或可重复执行的测试/检查脚本。
5. 已知限制列表，尤其是跨域外链验证、法律合规和 AdSense 最终审核不可由工具保证。

## 14. 实现完成后的答复格式
